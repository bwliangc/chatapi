# 幸运秒活动

系统设置 → 功能开关 → 幸运秒活动，默认关闭。管理员菜单中的「幸运秒活动管理」始终保留，关闭开关后仍可创建未来活动和查看历史。用户排行榜在消费榜或幸运秒任一功能开启时显示，两个标签独立受各自开关控制。

每期活动独立保存名称、起止时刻、时区、总奖池和奖励份数。时间范围为 `[开始, 结束)`，例如包含 10 月 1 日至 7 日全天，应填写 10 月 1 日 00:00 至 10 月 8 日 00:00。界面按浏览器时区录入，存储绝对时刻并展示活动时区。最长 366 天、最多 10000 份。每份至少 0.000001；金额用整数微单位随机拆分，总和严格等于奖池。创建后金额与中奖秒固定，不允许重新抽取或修改；可终止后创建下一期。不同活动可重叠，分别发奖。

## 参与与结算

- 请求在网关入口、鉴权和上游调用之前登记资格。共享数据库时间决定中奖秒，同一秒按数据库入口登记顺序确定先后，避免不同节点的系统时钟偏差。
- 文本、嵌入、搜索、同步图片以及 Gemini generateContent / streamGenerateContent 请求参与。异步图片/视频任务、批处理和持久长连接不参与。
- 成功提交的正金额余额扣费或订阅消费才确认有效。资格更新与计费在同一事务；失败、零消费和重复计费不构成新的有效资格。
- 先到请求尚未确定结果时，后到请求即使已完成也不能抢奖。先到请求无有效计费时顺延。异步计费任务共享引用计数，请求处理器返回不会提前放弃资格。
- 每秒结束后，后台锁定奖项，在一个事务中确认赢家、增加余额、保存记录。多个节点、重复巡检不重复发奖。每个用户允许多次中奖，多个活动独立结算。
- 无人命中的奖励过期，不顺延至其他秒，不保证奖池全部发完。关闭总开关或终止活动后，不再受理新请求；已经受理的资格继续结算。
- 节点每秒续约；节点失联超过 5 分钟后，仍无成功计费记录的待定资格视为失效。已提交的有效资格不受重启影响。余额缓存失效持久化排队，失败后重试。

## 数据与接口

迁移 `241_lucky_second.sql` 创建活动、奖项、请求候选、节点租约表。服务启动时自动迁移。奖励记入 `users.balance`，发奖记录保存在奖项表，不生成兑换码。

管理员接口（既有管理员认证、审计和限流）：

- `GET /api/v1/admin/lucky-second`：分页活动与发放汇总。
- `POST /api/v1/admin/lucky-second`：创建，字段 `name / starts_at / ends_at / timezone / total_amount / reward_count`；金额为十进制字符串，时间为 RFC3339。
- `POST /api/v1/admin/lucky-second/:id/cancel`：幂等终止。
- `GET /api/v1/admin/lucky-second/:id/slots`：分页奖励明细，包含未发生的中奖秒，仅管理员可见。

用户活动卡片显示「我的累计奖励」，按当前登录用户和本期活动汇总已发放金额。未中奖显示 $0.00，不受中奖记录分页影响，不计入待发或过期份额。

登录用户接口：

- `GET /api/v1/lucky-second`：分页活动与汇总，`my_awarded_amount` 为当前用户在各期活动中已到账的累计金额（十进制字符串）。用户身份取自登录会话。
- `GET /api/v1/lucky-second/:id/awards`：仅已发奖记录；其他用户邮箱脱敏，不返回用户 ID、请求 ID 或未来奖项。

总开关为 `lucky_second_enabled`，贯穿设置保存、公开 API 和 HTML 首屏配置注入。关闭时用户接口返回 404，管理员历史管理不受影响。
