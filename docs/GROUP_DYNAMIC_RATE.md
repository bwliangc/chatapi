# 分组动态倍率

管理员在「分组 → 创建 / 编辑 → 按分组用量动态调整倍率」开启，并填写最低、最高**基础倍率**。默认关闭，已有分组维持固定倍率。上下限允许为零，最多保留 4 位小数。

开启后，以整个分组的 `input_tokens + output_tokens + cache_creation_tokens + cache_read_tokens` 为用量口径。计入所有用户的已记录用量，用户专属倍率不会改变用量统计；不使用扣费金额。失败且未生成用量记录的请求不计入。

每 5 分钟执行一次计算：

1. 将当前时刻对齐到 5 分钟边界，取之前完整 1 小时的 Token 总量。
2. 取该窗口之前最多 7 天的完整小时桶，包含零用量小时。新分组、日志保留范围以外及不足一小时的历史不补零。
3. 历史小时用量的 P20 对应最低倍率，P90 对应最高倍率，中间线性插值，范围外封顶 / 保底。
4. 当 P20 和 P90 相等时，改用从零到 `max(历史最大用量, 2 × P90)` 的区间；全零历史按当前是否有用量选择最低 / 最高目标。
5. 每次将当前倍率向目标倍率移动 25%，四舍五入到 4 位小数，并限制在配置范围内。至少需要 24 个完整历史小时，否则仅将原倍率限制在范围内。

例如范围为 0.5–2.0、当前倍率为 1.0：当前用量处于历史低位时，下一次倍率为 0.875；达到历史高位时，下一次为 1.25。后续周期继续平滑调整。

计算结果写入原有 `rate_multiplier`，分组列表、价格展示、利润准入及计费继续读取同一个已发布值。用户专属倍率优先；订阅高峰倍率照常叠加，因此最终有效倍率可能超出这里的基础倍率范围。独立图片 / 视频倍率与显式工具定价维持既有规则。

请求使用其鉴权分组快照，后台发布触发持久化鉴权缓存失效及调度缓存更新；缓存传播期间可能存在短暂的新旧倍率过渡，已进入处理的请求不追溯改价。用量日志保留实际采用的计费倍率。关闭动态倍率时保留当前值，可以手动修改。

后台任务独立于仪表盘聚合开关。数据库比较更新保证同一 5 分钟周期最多发布一次，且计算期间的管理员修改不会被旧计算覆盖。统计或发布失败保留已发布倍率，记录错误并等待下次重试。需要保留足够的使用日志；系统以最早仍保留的用量时间限制可用历史。

升级启动时应用 `237_group_dynamic_rate.sql`。管理员 API 的创建 / 更新字段为 `dynamic_rate: { enabled, min, max }`，管理员分组响应额外返回 `dynamic_rate_updated_at`。所有配置变更仅对主动开启的分组生效。

## 分组倍率看板

登录后访问 `/group-rates`。在「系统设置 → 功能开关 → 分组倍率看板」开启「显示分组倍率看板菜单」，普通用户及管理员个人菜单会出现入口。默认关闭；该设置只隐藏菜单，不禁止已授权用户通过链接访问。

看板沿用 API Key 可绑定分组的权限规则，只展示启用且当前用户有权使用的分组，包括显式授权的专属分组和有效订阅。限制公开分组、订阅过期及授权撤回均生效。

页面每 30 秒刷新一次，展示当前基础倍率、动态上下限、用户专属倍率及当刻高峰叠加后的倍率，以及近 1 / 24 小时请求数、Token 总量、输入 / 输出 / 缓存构成和小时趋势。统计是整个分组的已记录用量，非个人用量，不包含用户或账号明细。趋势首尾为部分小时；统计窗口采用连续 24 小时而非自然日。

接口为 `GET /api/v1/groups/board`，必须登录。统计按授权分组集合合并查询并缓存最多 30 秒；每次请求重新验证分组权限和读取当前倍率，个人倍率不进入共享缓存。页面在后台暂停轮询，返回时刷新；请求失败时提示旧数据，失去登录权限时清空显示。
