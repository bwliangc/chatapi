# 模型一致性与定时降智检测

在系统设置启用模型检测后，可在「模型检测」页手动检测，或在页面下方配置定时检测。

- 定时配置默认关闭，默认间隔 360 分钟；可设置 15–10080 分钟。
- 支持搜索、跨页多选最多 100 个 OpenAI / Anthropic OAuth 或 API Key 实际账号。可批量应用一个参考库模型，也可逐账号选择其可用文本模型；不支持影子账号、合成账号或非文本模型。
- 保存并启用后，新账号进入后台队列。后台每 15 秒检查任务，按到期时间依次执行；任务繁忙时实际执行时间会晚于页面显示时间。关闭页面不影响执行，服务器重启后继续读取数据库配置，不追补错过的每一轮检测。
- 间隔按上次任务领取时间计算。修改间隔会调整下一次到期时间。关闭定时配置阻止后续领取，已开始的检测会完成；系统总开关同时约束手动和定时检测。
- 每次检测会消耗所选账号的上游额度，沿用原有最多 6 次采样、账号并发限制和十分钟超时。不可调度或请求失败时记录为检测失败，并在下次周期重试。

账号管理的「降智检测」列展示该账号最近一次检测的模型、时间和状态。手动与定时检测均保存结果；旧版本未保存的手动结果无法补回，首次重新检测前显示「未检测」。

「特征一致」表示与声明模型的参考特征相似；「疑似降智」对应原检测器的 `suspected_mismatch`，仅表示更接近其他候选，不能证明能力降低或模型身份。结论不明确、样本不足、模型未收录、检测失败、取消均独立展示。

实现使用 settings 中的 `model_detection_schedule_v1` 保存配置与各账号到期时间，以 CAS 原子领取，防止多实例重复领取同一轮。每账号还使用有期限的数据库检测锁，防止手动与定时检测跨实例重叠。进程异常退出后锁最多 11 分钟到期；已领取任务按下一周期恢复。

最近检测结果保存在 `accounts.extra.model_detection_snapshot`，包含状态、请求模型、检测时间、判定原因和最相似候选；不存原始探测回答。账号普通编辑保留数据库中最新快照，批量编辑与 Extra 更新接口不能覆盖该字段。

状态旁的历史图标打开该账号的检测历史弹窗，按最近记录优先分页展示检测时间、请求模型、状态、来源、判定原因和候选模型。关闭模型检测总开关后仍可查看历史。

迁移 `242_model_detection_history.sql` 新增独立历史表，并将已有账号的最新快照保留为一条「已有结果」记录；更早未保存的结果无法恢复。新检测以同一条原子 SQL 更新最新快照并追加历史，手动、定时、失败和取消的结果均记录，拒绝启动的重复任务不产生历史。历史不放入账号列表的 Extra 字段，不会随列表请求反复加载。
